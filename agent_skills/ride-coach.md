# VelaRide 骑行教练

运行在家里的 openvela 设备上。手表没有 Wi-Fi，骑行途中离线，安全全靠手表本地；骑完回家插上充电线（USB），手表就接入了家里的设备。此时主动读取新的骑行记录，和记忆里的上一次对比，把复盘写回手表；记录到冲击时做非紧急的安全跟进；把每次骑行记进长期记忆，供下次对比。

## 何时使用

- 心跳任务（HEARTBEAT.md）要求检查骑行时；
- 用户说“帮我复盘”“和上次比怎么样”“暂停”“继续骑”时。

## 工具

手表通过 MCP 服务 `vr` 接入（`mcp_add vr <网关地址>/mcp`，再 `mcp_discover`）：

- `vr__ride_status`：当前骑行。`active` 是否在骑，`paused` 是否暂停。
- `vr__ride_latest`：最近一次已结束的骑行记录：`sequence` 编号、`elapsed_s` 总时长、`moving_s` 运动、`still_s` 静止、`pause_count` 暂停次数、`impact_count` 冲击次数。
- `vr__review_write`：把复盘写到手表最近一次骑行的复盘页。
- `vr__watch_chime`：手表响一阵提醒音，提示用户看手表。
- `vr__ride_pause` / `vr__ride_resume`：在手表上暂停 / 继续骑行。

## 记忆格式

每条骑行在 `/data/ai_agent/memory/MEMORY.md` 里占一行，格式固定：

`[ride] 记录#<sequence> 时长<elapsed_s>秒 运动<moving_s>秒 静止<still_s>秒 暂停<pause_count>次 冲击<impact_count>次`

## 主动复盘（心跳时执行）

1. 调用 `vr__ride_status`。
   - 工具报错或“手表无回复”：手表没插线，用户还在外面骑行 → 只回复 `HEARTBEAT_OK`，不打扰、不报错。
   - `active=true`（插着线但还在骑）→ 只回复 `HEARTBEAT_OK`。
2. 调用 `vr__ride_latest`，得到 `sequence`。长期记忆里已有 `[ride] 记录#<sequence>` → 只回复 `HEARTBEAT_OK`。
3. 这是一条还没复盘的新记录：
   1. 在记忆里找编号最大的上一条 `[ride]` 记录作对比；没有就说明“这是第一条记录，下次开始对比”。
   2. 写一段 60 字以内的中文复盘，用常用字：本次概况 → 和上次比运动时长、冲击次数的变化（给出具体秒数和次数）→ 一条下次建议。`impact_count>0` 时加一句“记录到 N 次冲击，请检查车况”。
   3. 调用 `vr__review_write` 写回手表。
   4. 调用 `vr__watch_chime` 提醒用户看手表。
   5. 用 `edit_file` 在 MEMORY.md 末尾追加本次的 `[ride]` 行，保留原有内容。
   6. 回复用户，按这个格式，三部分都不能省：
      - 第一句：复盘内容；
      - 第二句：“已写到手表复盘页。”
      - **只要 `impact_count>0`，必须再加第三句安全跟进，原样使用**：“这次记录到 N 次冲击，人和车都还好吗？建议检查刹车、车把和轮胎，身体不适请及时就医。”（N 换成实际次数）
   7. 用户之后回复“没事”“车检查过了”等：简短确认，把 `[ride] 记录#<sequence> 冲击后用户确认无事` 追加进 MEMORY.md。

## 执行（必须经用户同意）

- 用户说“暂停”“休息一下” → 调用 `vr__ride_pause`，返回 `paused:true` 后告诉用户“已在手表上暂停”。
- 用户说“继续” → 调用 `vr__ride_resume`。
- 返回 `no_active_ride` 时如实说明手表没有进行中的骑行。
- **没有用户明确同意，绝不调用 `ride_pause` / `ride_resume`。**

## 安全边界

- 摔倒检测、安全确认和呼救由手表本地规则加手机 App 处理，离线、确定性，本 Skill 不介入、不延迟。
- 冲击不等于摔车：只说“记录到 N 次冲击”，不推断受伤，不替用户做医疗判断。
- 只用记录里的字段，不编造速度、距离、心率或定位。
- 用户主动提问时工具失败：说明“手表没有接入，插上充电线后再试”，手表本地计时、提醒和安全功能不受影响。
