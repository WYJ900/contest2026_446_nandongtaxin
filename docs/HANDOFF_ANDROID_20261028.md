## 实现和数据边界

- `RideHistory.java` 保存手机历史模型；设备地址 + 序号 + 固定骑行摘要用于去重。
  不同手表不会混入同一条；同地址、同序号但数据不同会另存。
- 私有文件 `rides-v1.bin` 使用版本头、数量边界和 CRC，`HistoryFile` 使用 AtomicFile 写入并回读确认。
  保存失败不会更新内存显示；读取失败不会删除或静默覆盖历史。
- Activity 重建共享同一个进程内历史对象，防止旧 Activity 的保存与新 Activity 的加载相互覆盖。
  BLE 单工作线程协议保持原状。
- 0.1.1 的 `latest_record` / `synced_at` 在后台迁入，未知时间标为未知，未知设备独立标记。
- 分享为用户点击后的系统文本分享；CSV 为用户自行选择保存位置，无新增权限或云上传。
  UTF-8 BOM、引号/换行转义、公式前缀保护已测。
- 最多 5000 条，不自动淘汰；满额后仍可读取、更新已有条目、导出，但不能新增。
- 当前表端只提供最近一次骑行，App 仅积累实际同步到的记录；不能补回未同步就被覆盖的旧记录。
- 记录没有骑行日期和轨迹，界面明确标示同步时间。若同一地址在重置后产生完全相同的序号和摘要，
  当前协议无法区分。完整唯一 ID 和发生时间需要以后独立扩展协议。

## 手机到货后

覆盖安装 0.1.2（不要卸载 0.1.1），检查权限/扫描/连接/校时/第 11 条记录同步。
重复同步应只显示一条；重开 App 与旋转屏幕后仍能查看，旧缓存应迁入。
再检查备注成功后留存、详情分享、CSV 中文与换行、保存取消和断线浏览。
不同骑行记录用真实开始/结束产生；不要为测试覆盖现存骑行或备注。

之后优先在现有稳定手表基础上单独移植手机 GPS 生命周期扩展，按阶段做旧功能回归。
不得为 GPS 刷回有触摸退化记录的 v18/v19。夜骑模式的颜色、手势与自动明亮退出仍待用户确认。
