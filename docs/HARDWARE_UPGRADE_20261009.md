# 2026-10-09 真机与多模型网关升级

本记录取代早期文档中“BLE 尚未打通”的状态描述。历史测试和旧固件仍保留，不能
将单次连通测试等同于长期可靠性验证。

## 已完成修改

- SF32LB52 HCI 发送先将完整帧写回共享 SRAM，再触发 mailbox；接收不再依赖
  缓存中的零长度通知。移除伪造 HCI 命令成功回复，使用控制器真实能力和响应。
- SRAM 普通堆和黄山派链接区截止到 `0x2007fb00`，预留顶部 256 字节 ROM 配置及
  1024 字节 mailbox，防止蓝牙帧覆盖 LVGL 对象。
- GATT 回调只接收与排队，业务任务处理持久化和分片通知，避免占满系统工作队列
  的发送缓冲。断线后重新广播，重复启动受到保护。
- 增加 `ride_latest`、暂停和休息计数、超长帧丢弃，以及按骑行序号拒绝过期复盘。
- Flash 初始化、页写入和恢复 AHB 读取在中断保护范围内执行，避免 BLE 中断在
  NOR 指令切换时执行 XIP 代码。初始化增加互斥保护。
- 修复 NVS 启动缓存按“新到旧”遍历时被旧条目覆盖的问题，保留每个缓存桶首次
  遇到的最新条目（包括删除标记）。此前复盘数据实际已写入，但重启会误读旧清零块。
- 屏幕异步路径补齐开启操作；CPU 渲染的 PSRAM 表盘快照改为 64 字节对齐、
  带尾部填充并在缓存失效前写回像素，避免丢弃绘制结果或相邻缓存行。
- 增加 `velaride lcd-status` / `lcd-wake` / `lcd-test` 诊断命令。色条模式仅用于
  测试，执行 `lcd-wake` 可恢复正常界面。
- 移除未接入 GPS/心率硬件时的固定速度、距离推算和固定心率；无数据时显示 `--`。
- 正文中文子集字库扩充为 3,770 个常用字和标点，采用 19 px / 2 bpp，保留
  `velaride_font_cn_20` 接口名。网关与固件通过同一字符表生成并做一致性测试。
- 复盘保存后由 UI 线程自动显示对应记录，重启后复盘页面读取真实保存内容。
  原有演示页的固定速度、距离、骑行时长和示例复盘也已移除。
- 网关支持 OpenAI Chat Completions、Responses、Anthropic Messages 和兼容中转站。
  密钥只存在于安全启动器及子进程环境中；接口返回不包含密钥或完整服务地址。

## 黑屏复发与 CPU 绘制对照

在上述链路验证后，用户报告重启后再次黑屏。系统任务仍在运行，LCD 软件状态为
power=100，但唤醒和强制重绘未恢复画面。因此，串口读回成功不能作为显示正常的证据。

保留原有 SRAM 双缓冲、LCD 和触摸配置，仅关闭 `CONFIG_LV_USE_DRAW_EPIC`，重新生成
配置头并完成全量重新编译。生成头文件和链接符号均确认未启用 EPIC 绘制后端。
用户确认烧录后表盘、连续滑动和触摸正常，但随后第一次复位再次黑屏。
因此关闭 EPIC 并未解决故障，不能将 EPIC 判定为根因，也不能将此镜像标记为稳定版。
该 CPU 绘制诊断版本已被后续面板状态恢复版本取代。记录与复盘读回正常只证明持久化链路。

后续已读到黑屏时面板电源/显示状态从 9Ch 变为 0Ch、像素格式从 55h 变为 77h，
独立重初始化后恢复。新增实际状态检查和恢复，详情与最新验证状态见
[复位黑屏排查记录](DISPLAY_RECOVERY_20261009.md)。

同时修正本机增量构建脚本：活动 `.config` 更新后重新生成 `config.h`，防止配置已改
但实际镜像仍沿用旧绘制后端。Windows 与 WSL 板级配置已同步。

## 工具与复现

当前 CPU 绘制固件大小 9,976,368 字节，配置区前仍有 50,640 字节；SHA-256：
`5D99290D8EAD4FA44DACA2C8EED764D5CAB8D4093DD9F017E1F0590D47B734FF`。
20 px / 2 bpp 的全常用字试验镜像超过边界 2,684 字节，已被检查拒绝，未烧录。
构建与 Windows 烧录脚本均检查配置区边界，不能绕过检查烧录超限镜像。

```powershell
cd web-gateway
npm test
.\start-ai.ps1
```

安全启动器使用 Node watch 模式。首次网页 BLE 连接需在浏览器设备选择器中选择
`VelaRide`。连接后依次使用“读取最近骑行记录”“生成复盘”“回传复盘到手表”。

`scripts/ble_probe.py` 使用 Python 3.13 + Bleak 3.0.2，支持多轮重连、校时以及从
本机网关取得真实 AI 结果并回传；`--require-ai` 会将本地降级视为测试失败。
`scripts/serial_probe.py` 使用 pyserial，默认保持 DTR/RTS 关闭，仅 `--reset` 复位。
串口诊断可能中断当前用户操作，日常网关应使用 BLE。

本轮在现有 Ubuntu-22.04 WSL 工作区增量编译并多次烧录，未声称在全新 checkout
完成全量复现。源码与构建日志对应的警告仍包括已有 RWX 链接段；旧驱动的混合
命名、格式不完全满足全文件 checkpatch，不能写成全部静态检查通过。
