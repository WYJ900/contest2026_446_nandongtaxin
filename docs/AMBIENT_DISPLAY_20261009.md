# S3：环境光与屏幕设置

日期：2026-10-09。用户确认 S0/S1 “页面和触控都 ok”后继续本阶段。

## 产品行为

入口：功能键菜单 → 设备 → 屏幕设置。

- 实时显示板载光线传感器的照度估计，失效时显示“暂不可用”。未做外壳透光率和标准照度计校准，不作为精密测量仪器。
- 柔和、标准、明亮分别对应 20%、50%、80% 的面板亮度控制值。点击任一档位切换为手动。
- 自动调光初始关闭；开启后根据照度在 25%、50%、80% 之间缓慢变化，每秒最多改变 5 个百分点。
- 平滑系数 0.25；暗/普通边界为 15/30 lux，普通/亮边界为 250/350 lux；跨界连续 3 次才换档。
- 数据失效时立即回到手动档位。自动调光不会触发熄屏、复位或切断屏幕共用供电。
- 手动档位、自动开关在后台保存。自动亮度变化不写闪存。保存失败显示错误，可再次点击重试。
- 返回键从屏幕设置回设备页，再返回表盘；骑行会话不允许进入设置页。

## 实现

新增 NuttX LTR303 uORB 下半部驱动，注册 `/dev/uorb/sensor_light0`。采用非阻塞 fetch，打开时启动、最后关闭时待机。
固定 1 倍增益、100 ms 积分、500 ms 测量周期；应用后台每秒读取。按地址递增一次读取 CH1/CH0 四字节。
无新数据返回 `EAGAIN`；无效/饱和/意外增益返回错误，不发布假读数。红外计数不伪装为 SI 照度。
上层超过 3 秒未收到新数据即标记失效，并尝试关闭/重开恢复采样。

新增独立亮度 ioctl，与原有电源控制区分。界面线程在帧间等待上一笔传输完成后写亮度寄存器。
HAL 写入失败会反馈到界面；驱动只缓存成功写入的值。面板状态丢失后，原有恢复逻辑重新初始化并恢复该亮度。
CPU 绘制、SRAM 双缓冲、共享供电及原记录存储格式保持现有基线。

## 实机阶段结果

安装镜像 `velaride-hardware-s3-20261009.bin`，9,274,664 字节，距配置分区 752,344 字节。
SHA-256：`B6B56C603C2707078D9C8F3BCE62CFB840D2C09AEB1C96C2C74D971BAD5CF08F`。

- 修正首样本等待后，首轮累计 41 个有效光线样本、0 失败；当时估计约 12.19 lux。
- 手动 20%/80% 对应亮度寄存器 `0x33`/`0xCC`；显示状态保持 `0x9C`，像素格式 `0x55`。
- 主动调用一次面板恢复后读回 `0xCC`，设置保留。该轮恢复计数 1 来自主动作业，不是自动故障恢复。
- 整机复位后仍为手动 80%，设置保存/读取通过；光线采样恢复，读到约 15.74 lux。
- 自动调光读回 80% → 65% → 50% 的变化，符合每秒最大 5 个百分点限制。
- 原第 7 条记录仍在，不能作为本阶段新骑行闭环证据。
- 最终读回：109 个有效光线样本/0 失败，11 次 ADC 采样/0 失败；353 次送屏全部完成，重启后恢复计数 0。
