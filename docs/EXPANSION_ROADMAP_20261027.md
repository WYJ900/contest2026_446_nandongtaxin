## 1. 先摸清家底

### 1.1 板上已有、能用的资源

| 资源 | 现状 | 可做什么 |
| --- | --- | --- |
| SF32LB52 + PSRAM，LVGL + EPIC | 滑动约 52 Hz，空闲堆约 5.2 MB | 动画、地图、图表 |
| 390×450 AMOLED + 触摸 | 正常 | 黑底省电，适合常亮的简化表盘 |
| LSM6DSL 六轴 | 抬腕、水平仪、冲击检测已在用 | 摔车识别、自动暂停、计步（芯片自带计步器） |
| MMC5603 地磁 | 已采样，北向未验收 | 指南针、返航方向 |
| LTR303 光线 | 自动调光已在用 | 夜骑模式、隧道提醒 |
| 麦克风 + 8 Ω/1 W 喇叭 | 诊断命令已验收 | 提示音、语音备忘、语音播报 |
| BLE（zblue） | **已编入主机（Central）和扫描（Observer）**，`BT_MAX_CONN=1` | 除了连手机，还能连心率带、踏频器 |
| TF 卡座（SPI1：PA24/25/28/29） | 驱动已编入，开机自动挂到 `/data/tf`；目前没插卡 | 见第 2 节 |
| 侧键、LED（PA32） | 已在用 / 未用 | LED 可做低电量或录制指示 |

### 1.2 没有、需要另买或依赖手机的

| 缺什么 | 影响 | 解决办法 |
| --- | --- | --- |
| GPS | 没有真实速度、距离、轨迹 | 由手机 App 提供（10-26 已有雏形） |
| 气压计 | 没有爬升和坡度 | 由手机 GPS 高度提供（误差大），或外接 BMP390 等 |
| 心率 | 没有心率区间 | 用 BLE 心率带（标准协议，见 4.1） |
| 电池 | 只能接 USB，不能实际骑行 | 板上已有 AW32001 充电芯片（I2C2：PA10/PA11），买电池后接入 |
| 振动马达 | 不能静音提醒 | 焊扁平马达，控制脚 PA20（PWM） |

### 1.3 两个硬约束

1. **固件空间只剩约 424 KB**：应用区上限 10,027,008 字节，当前 9,592,552 字节。
   字体、图片、音频继续放进固件很快就满了。**TF 卡最大的价值之一，是把素材从固件里搬出去。**
2. **屏幕供电对 USB 很敏感**：官方说明里写过“屏幕拉低 USB 电源会导致反复 SFBL”，
   而 TF 卡写入时有电流尖峰。接 TF 卡后要专门做一次复位测试，加上 TF 连续写入时的静置测试。

## 2. 64 GB TF 卡

### 2.1 使用前提（必须先做）

- **格式化成 FAT32，不能用 exFAT。** 64 GB 卡出厂一般是 exFAT，NuttX 的 vfat 驱动不支持。
  Windows 自带工具不允许把大于 32 GB 的卡格式化为 FAT32，需要用 guiformat
  （FAT32 Format）之类的工具，簇大小选 32 KB。
- 当前配置**没开长文件名**（`CONFIG_FAT_LFN` 未设置），文件名只能是 8.3 格式，例如 `RIDE0012.BIN`。
  可以先按 8.3 命名，以后再单独评估是否打开长文件名；打开会增加固件体积。
- 速度：SPI 20 MHz，理论上限约 2.5 MB/s，实际预计 0.5–1 MB/s。存数据、播放音频够用，看视频不够。
- 第一个补丁只做“插卡 → 挂载 → 读写一个测试文件 → 拔卡不死机”，并跑完整的基础回归。

### 2.2 TF 卡能带来的功能

| 编号 | 功能 | 说明 | 工作量 | 依赖 |
| --- | --- | --- | --- | --- |
| T1 | **完整骑行历史** | 现在只保存最近一条记录。改成每次骑行一个文件，手表上列历史，并做周/月统计 | 中 | 只需 TF |
| T2 | **骑行黑匣子** | 骑行时用环形缓冲记录六轴 50–100 Hz 数据；检测到冲击时，把前后各 30 秒落盘。可用于事后复盘、调摔车阈值、AI 分析 | 中 | 只需 TF |
| T3 | **持久化系统日志** | syslog 和复位原因写入 TF，按天轮换。10-26 那种“正常 → 黑屏 → SFBL”的过程以后能留下证据 | 小 | 只需 TF；**对排障最有用，建议最先做** |
| T4 | 语音提示音包 | 事先在电脑上用 TTS 生成“已骑行 30 分钟”“注意休息”等 WAV 放进卡里，手表只负责播放；不占固件空间，也不需要联网 | 中 | TF + 正式音频设备（第 5.1 节） |
| T5 | 语音备忘 | 骑行中按住侧键录 5–30 秒，存到卡里，回家后在手机上听或转写 | 中 | TF + 麦克风 |
| T6 | 表盘、主题、字体包 | 图片和字体从固件挪到卡里，开机加载到 PSRAM；空出固件空间，也能“换皮肤” | 中 | TF；要注意加载速度 |
| T7 | 离线地图和路线 | 在电脑上把路线和小范围地图切成 390×450 的图块放进卡里，手表显示当前位置和路线（位置来自手机 GPS） | 大 | TF + 手机 GPS |
| T8 | 屏幕截图 | `velaride screenshot` 把当前帧存为 BMP，用于比赛文档、视频和 UI 走查 | 小 | 只需 TF |
| T9 | 数据导出 | 骑行记录导出为 GPX/CSV/FIT，可通过手机 App 读走，或拔卡后在电脑上读 | 中 | T1 |
| T10 | AI 资料库 | 历史骑行摘要存在卡里，AI 复盘时能对比“这次比上周”，不只看单次 | 中 | T1 + 手机/网关 |

建议顺序：T3 → T1 → T8 → T2 → 其余。

## 4. 蓝牙外设（Central 已编入）

BLE 主机和扫描功能已经编入，只是 `CONFIG_BT_MAX_CONN=1`，现在这一个连接被手机占用。
要同时连手机和外设，需要把连接数调到 2–3，并评估内存和射频时间片。
这属于改动共享的蓝牙配置，必须单独做一个阶段并完整回归旧 BLE 功能。

| 编号 | 外设 | 协议 | 价值 |
| --- | --- | --- | --- |
| 4.1 | 心率带（胸带或臂带） | 标准 Heart Rate Service 0x180D | 心率、区间、AI 复盘用强度 |
| 4.2 | 速度/踏频传感器 | 标准 Cycling Speed and Cadence 0x1816 | 不依赖 GPS 的速度和距离，隧道里也能用；踏频 |
| 4.3 | 功率计 | Cycling Power 0x1818 | 进阶训练 |
| 4.4 | 智能车灯、尾灯雷达 | 多数是厂商私有协议 | 后方来车提醒（需要逐款研究，风险高） |
| 4.5 | 手机媒体控制 | 通过 App 自定义命令 | 骑行中切歌、调音量 |

4.1 和 4.2 都是标准协议，三四十元就能买到，**很适合作为比赛演示**，不需要等手机 GPS。

## 7. 电池接入后才有意义

- AW32001 充电芯片驱动、电量百分比、充电状态，ADC 需要校准（S1b）。
- 低功耗：熄屏时降频，BLE 调长广播间隔，常亮表盘（AMOLED 只点亮少量像素）。
- 续航实测，并给出“骑行模式能用几小时”的明确数字。
- 电池供电后，10-26 那种 USB 电压被拉低的风险会降低，但仍要复测。

## 8. 工程和框架

| 编号 | 事项 | 原因 |
| --- | --- | --- |
| E1 | **源码统一到团队仓 git，每个阶段打标签** | 现在源码分散在 4 棵 WSL 树和多个副本里，靠文档对应固件版本 |
| E2 | 新功能都用 Kconfig 开关，默认关闭 | 关掉时与上一阶段二进制等价，回归对比只剩一个变量 |
| E3 | `boot_check.py` 扩展成完整验收 | 加入旧 BLE ping/读记录、静置 N 分钟、TF 卡挂载检查，统一输出 JSON |
| E4 | 开机记录复位原因 | 区分上电、看门狗、RTS、软件复位；配合 T3 写入 TF |
| E5 | 素材迁到 TF（T6） | 缓解固件空间只剩约 424 KB 的问题 |
| E6 | 设置子页常驻 | 10-17 遗留的进出设置约 60–80 ms 卡顿 |
| E7 | 蓝牙 OTA | 无线升级固件；本板没有独立 bootloader，做法需要专门设计，**变砖风险高，放到最后** |

## 10. 需要用户提供或决定的

1. TF 卡：先按 2.1 格式化成 FAT32（簇 32 KB）。格式化会清空卡里的数据，请先备份。
2. 是否购买：心率带（标准 BLE）、速度/踏频传感器、电池（型号要和 AW32001 的充电参数匹配）、振动马达。
3. 求助功能的联系方式：短信、微信还是只在手机上响铃？涉及手机权限和隐私，需要你来决定。
4. 优先级：第 9 节的顺序是否要调整，比如为了比赛先做 TF 卡和心率带。
